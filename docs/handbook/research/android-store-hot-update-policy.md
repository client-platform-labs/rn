# 国内 Android 应用商店：JS / CodePush 类热更新政策调研

GitHub: [#373](https://github.com/client-platform-labs/rn/issues/373)，父图 [#319](https://github.com/client-platform-labs/rn/issues/319)。对照操作手册 [android-store-submit.md](../operations/android-store-submit.md)。

**调研日：** 2026-11-16  
**问题：** 各店是否公开允许或禁止「不换商店 APK、动态下发代码以改变应用行为」的热更新（含 JS Bundle / CodePush 一类）。  
**原则：** 优先引用商店官方一手文档；公开文档未写明则判 **未核实**，不臆造。  
**判决取值：** `允许` | `禁止` | `受限` | `未核实`

**对照（非重点）：** Apple App Store Review Guidelines **2.5.2** 禁止下载、安装或执行会引入或改变应用功能的代码（教育等窄例外除外）；与华为 3.13 同属「改行为的动态代码」高压线。出处：<https://developer.apple.com/app-store/review/guidelines/>（访问日 2026-11-16）。

## 1. 华为应用市场（AppGallery）

- **判决：** 禁止  
- **规则（摘录/转述）：**  
  - **3.13**：应用不得绕过审核机制进行自动更新（应使用华为应用市场下载可执行应用更新的组件）；**不得从其他来源下载、安装或执行会修改、替换或更新应用本身特性或功能的代码。**  
  - **2.5**：不得下载、安装或运行第三方恶意代码以更改应用功能，**包括但不限于滥用热更新或插件化技术动态加载恶意代码。**  
- **一手 URL：**  
  - 《应用审核指南》§3 应用功能：<https://developer.huawei.com/consumer/cn/doc/50104-03>（含 **3.13**）  
  - 总览入口：<https://developer.huawei.com/consumer/cn/doc/app/50104>  
- **访问日：** 2026-11-16  
- **说明：** 3.13 字面覆盖「改特性/功能的代码下发」，与 CodePush / JS Bundle 改行为高度重合。公开文档未单独开绿灯给「仅修 bug 的热修」。

---

## 2. 荣耀应用市场（Honor）

- **判决：** 未核实  
- **规则（摘录/转述）：** 现行《荣耀应用市场审核规范》**未出现**「热更新 / 热修复 / 动态加载代码 / 插件化」等表述。相近条款包括：须提交最新正式版、应用内不得提示有更新版本；不可在审核时隐藏违规内容、上架后再开启；官方更新能力文档只谈经应用市场 / 更新 SDK 的 **APK 自更新**。  
- **一手 URL：**  
  - 审核规范：<https://developer.honor.com/cn/doc/guides/100879>  
  - 自更新（商店 APK，非 CodePush）：<https://developer.honor.com/cn/doc/guides/101564>  
- **访问日：** 2026-11-16  
- **说明：** 不能从「未写」推断允许；亦不能写成禁止。工程上若要做 JS OTA，需另走商务/审核确认，本文不编造结论。

---

## 3. 小米应用商店

- **判决：** 受限  
- **规则（摘录/转述）：**  
  - **分级 L4「应用违规热更新」：** 使用热更新等手段对抗或逃避检测；例：内容或功能违规自动更新为博彩、色情等。  
  - **合规公告：** 治理通过「热更新」「热切换」变更内容及服务的违法违规行为；防止擅自更改 APP **主要功能、申请权限及个人信息收集使用场景和范围**；对集成热更新能力或「安装和执行可更改应用特性/功能代码」的产品持续巡查。  
  - **联运：** 上线后每次更新需重新提交审核，**不允许热更新**（联运场景硬性表述）。  
  - 通用《应用审核规范》本身**未**写「一律禁止一切热更新」。  
- **一手 URL：**  
  - 分级：<https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2196>（L4「应用违规热更新」）  
  - 联运：<https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1941>（文内：「不允许热更新」）  
  - 《开发者生态政策》安全 3.2：不得下载、安装或执行会引入或更改应用特性/功能的代码，亦不得含第三方加载可执行代码的 SDK — <https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1321>  
  - 合规公告（小米应用商店官方公众号）：<https://mp.weixin.qq.com/s/Z06VcUAT1R31FdcijEjuvQ>  
  - 审核规范（未点名热更新）：<https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1080>  
- **访问日：** 2026-11-16  
- **说明：** 能力本身多被巡查监管，而非公开「欢迎任意 CodePush」。生态政策 3.2 对「改特性的可执行代码」措辞很硬；分级把「违规热更新」落在 L4。改主功能 / 权限 / 隐私范围 / 规避检测属红线。联运包另有硬禁止。对外仍标 **受限**（非「商店书面允许」），联运场景按禁止理解。

---

## 4. OPPO 软件商店

- **判决：** 受限  
- **规则（摘录/转述）：**  
  - 安全：**动态加载恶意插件**——滥用热更新、热修复或插件化技术，在运行时动态加载**新的恶意代码**。  
  - 功能体验：不可出现应用启动后**强制更新，提示更新、热更新、或跳转至浏览器更新**等情况。  
  - 官方社区复查公告：点名部分开发者通过**线上热更、服务器内容动态切换**避开审核上架，平台加强复测与处置。  
- **一手 URL：**  
  - 《OPPO 应用审核规范》：<https://open.oppomobile.com/documentation/page/info?id=12131>（同内容入口亦见 `id=12131` 文档站）  
  - 合规复查公告：<https://open.oppomobile.com/bbs/forum.php?mod=viewthread&tid=5160>  
- **访问日：** 2026-11-16  
- **说明：** 公开条文打的是「恶意代码 / 规避审核 / 启动强制热更提示」，**没有**写成「任何 JS Bundle 下发一律禁止」。良性热修是否可过，文档未给正面白名单。

---

## 5. vivo 应用商店

- **判决：** 未核实  
- **规则（摘录/转述）：** 《应用审核规范》全文检索**无**「热更新 / 热修复 / 动态加载 / 插件化」。相近条款：  
  - 审核前后通过**服务端控制**应用内容、上架后开启违规服务 → 欺诈，可下架/封号；  
  - **9.2.3** 不得通过技术手段恶意妨碍、干扰或**规避**平台审核与巡查；  
  - **4.3.4** 请勿打开后提示更新版本，须提交最新版。  
- **一手 URL：** <https://dev.vivo.com.cn/documentCenter/doc/12>（页面更新时间 2026-10-29）  
- **访问日：** 2026-11-16  
- **说明：** 规避审核与服务端藏内容属红线，但公开规范**未**对 CodePush 类能力本身表态 → 保持未核实。

## 6. 应用宝（腾讯 MyApp / 腾讯开放平台移动应用）

- **判决：** 受限  
- **规则（摘录/转述）：**  
  - 赌博条款：APP **不能提供、内嵌、热更新**赌博内容及玩法（老虎机、炸金花等）。  
  - 暂不收录相关表述：**热更新包括但不限于恶意变更内容，切换 SDK 支付等。**  
  - 另有「未说明的隐藏特性或有悖描述」等功能条款，可间接约束「上架后改行为」。  
- **一手 URL：** 腾讯开放平台资料库《移动应用审核规范》  
  <https://wikinew.open.qq.com/#/iwiki/4007776097>  
- **访问日：** 2026-11-16  
- **说明：** 官方 wiki 明确约束的是「用热更新做涉赌 / 恶意改内容 / 换支付 SDK」等，**不是**对一切 JS OTA 的一刀切禁止。二级站点转载的全文可信度低于本 wiki，本文以 wiki 为准。

## 行业背景（非商店政策，仅备忘）

电信终端产业协会团体标准 **T/TAF 325—2026**《应用分发平台 APP 热更新安全审核要求》把热更新定义为动态下发并加载代码/资源/Web 页；要求分发平台登记热更新能力与目的，允许安全性更新，限制用热更新做违规、改主功能、改分类等。起草单位含荣耀、OPPO、小米、vivo 等。**该标准不是某一家商店的公开审核条款**，不能替代上表判决。

工信部信管函〔2023〕26 号等监管文件提出热更新管控要求，同上，属监管背景而非单店细则。

## 对本仓库（JS OTA / `ship update`）的读法

1. **华为：** 公开指南按「禁止从非应用市场来源执行改特性代码」理解；商店渠道的 JS 热更新风险最高。  
2. **小米 / OPPO / 应用宝：** 公开口径是「能力可存在，用途受限」——勿改主功能、勿躲审、勿涉赌/恶意；联运（小米）另有硬禁止。  
3. **荣耀 / vivo：** 公开审核文未点名 → **未核实**；不要在对外材料里写成「商店已允许」。  
4. 各店均强调「提审包须为最新、勿打开即逼更」；商店 APK 更新与自有 JS OTA 不是同一条通道。  
5. 本文只反映**公开政策文本**；实际过审与在架巡查以各店当期执行为准。
