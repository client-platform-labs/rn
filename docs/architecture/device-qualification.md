# 设备资格矩阵（device qualification matrix）

**Opened:** 2026-09-14 · 关联 #298 · 输入到「可企业推广」设备证据（enterprise-promotion-gates.md "Device evidence"）

## 为什么需要这张表

平台的设备验收曾隐含假设"在这台设备上跑过 = 平台可推广"。设备验收必须**显式记录每台设备的 ROM/型号 + 每 leg 的验证状态**，不合格项要能挡在企业推广证据之外。

> **勘误（#298 重定性）**：本表最初把 vivo V2425A 标记为 leg A 不合格，依据是"应用内写入不持久"。真机复核证明这是**误判**——死端口测试的完成 boot 按设计 reset 崩溃环计数器（release-boot.ts:342-345），且 chain-11 leg A 判据的观察窗口错（logcat -c 后只看最终 restart，错过 kill 循环中已触发的回滚）。修复判据（PR #304）后，vivo V2425A 上完整 chain-11 C/B1/B2/A **全部 PASS**。

## 设备验收纪律

- 每台新验收设备：先跑状态持久化探针（写入 → 重启 → 读回）确认基线，再进 leg 判据
- leg 判据必须观察**正确窗口**（chain-11 leg A 已修复：整个 kill 循环窗口，非单次 restart）
- 设备矩阵记录每设备验证状态；不合格项不得作为任何 leg 的证据

## 需补的验证（resume-when）

1. **扩大设备覆盖**：跑 ≥2 台其他设备（另一 OEM + 原生 Android）确认 leg A/B/C 全过，扩充矩阵（目前仅 vivo V2425A 一台）
2. 设备矩阵随验收持续更新

## 与验收流程的接线

- 每台新验收设备：先跑本矩阵的"状态持久化"探针（三机制写入 → 重启 → 读回），不合格直接标记，不进入 leg 判据
- 企业推广门禁的 Device evidence 引用本矩阵的设备清单，不合格设备不得作为任何 leg 的证据
