# 设备资格矩阵（device qualification matrix）

**Opened:** 2026-09-14 · 关联 #298 · 输入到「可企业推广」设备证据（enterprise-promotion-gates.md "Device evidence"）

## 为什么需要这张表

平台的设备验收曾隐含假设"在这台设备上跑过 = 平台可推广"。但 #298 证明**单设备验收会静默烙进设备病态**：
vivo V2425A (iQOO Neo10) / Android 16 / SDK 36 上，应用进程内写入（SharedPreferences commit/apply、同步文件）**全部不持久**（run-as 手动写同目录正常），导致崩溃环计数器不累计 → **leg A 自动回滚在该设备上永不触发**。

设备验收必须**显式记录每台设备的 ROM/型号 + 每 leg 的验证状态**，不合格项要能挡在企业推广证据之外。

## 矩阵

| 设备 | ROM / Android | 状态持久化 | leg A 崩溃环 | leg B 信任链 | leg C 静态 | 资格 |
| ------ | -------------- | ------------ | -------------- | -------------- | ------------ | ------ |
| **vivo V2425A**（iQOO Neo10） | OriginOS / Android 16 (SDK 36) | ❌ **应用内写入不持久**（#298 三机制铁证） | ❌ **FAIL**（计数器无法累计） | ✅ PASS（本次重验，leaf 签名 CRL + HBC） | ✅ | **leg A 不合格** |
| —（待补充） | — | — | — | — | — | 换设备验证后填 |

## 不合格的影响

- 该设备上，崩溃环自动回滚**无应用代码可修复**（ROM 层写保护）
- morning sweep 的 leg A PASS 与此矛盾，需复核（旧判据或不同构建）
- **不得**以该设备作为 leg A 的验收证据

## 需补的验证（resume-when）

1. **换 ≥2 台设备**（另一 OEM + 原生 Android 或模拟器）跑 leg A：
   - 若计数器正常累计 + 回滚触发 → 问题为 vivo/OriginOS 特有 → 矩阵标注 + 验收设备清单加白名单
   - 若同样失败 → 问题更广 → 升级为平台级持久化缺陷（模板文件迁移候选，见 #298）
2. 复核 morning leg A PASS 的构建与判据（旧 pid-change 判据可真空过，runbook §7.3 已换 OTADIAG 判据）
3. 模板持久化加固（file-based 迁移已在 DUT 实现并编译通过，未验证前不入模板——见 #298）

## 与验收流程的接线

- 每台新验收设备：先跑本矩阵的"状态持久化"探针（三机制写入 → 重启 → 读回），不合格直接标记，不进入 leg 判据
- 企业推广门禁的 Device evidence 引用本矩阵的设备清单，不合格设备不得作为任何 leg 的证据
