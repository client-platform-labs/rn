# RN 平台交付物全景（企业对外版）

> 本文面向企业决策者、技术负责人、合作方评审。内部票号、研发代号与验收流水一律不出现；口径对齐平台对外能力声明（L0–L5 企业推广层级）。
> 内部完整版（含工程细节）见 [`deliverables-inventory.md`](./deliverables-inventory.md)。

---

## 1. 平台是什么

**React Native 企业级交付平台**——覆盖一个 App 从「工程初始化 → 多业务模块并行开发 → 签名发布 → 设备端 OTA 下发与回滚 → 灰度与质量门禁 → 灾难恢复」的全生命周期，并提供一套**统一工业标准**同时支持两类宿主形态：

- **绿地（Greenfield）**：从零生成的 RN 新应用，原生壳 + 业务模块。
- **棕地（Brownfield）**：嵌入既有原生宿主（已有 iOS/Android 工程），以模块包方式增量接入，无需重写宿主。

两类形态共享同一条交付协议、同一个设备端 SDK、同一套质量与安全标准——**不是两个产品，是同一个平台的两条路径**。

**一句话**：`rn` 管「造工程」，`ship` 管「发布交付」，控制面服务管「设备端下发与回滚」，底层库被所有环节共用，治理文档把规则固化为契约与可执行门禁。

---

## 2. 能力分层

| 层 | 定位 | 交付物 | 面向角色 | 交付方式 |
|----|------|--------|----------|----------|
| **底层库** | 引擎无关契约 + RN 引擎适配 + 设备端 SDK，无业务逻辑 | 契约与门禁库 / 引擎适配器 / 设备端 OTA 客户端 | 移动平台团队 | 以依赖包形式随平台分发，编译进宿主 |
| **框架** | 把「工程」和「壳」造出来 | 开发者 CLI（`rn`）+ 脚手架模板 + 生成式注册表 + Metro 解析器 + 开发会话 | 应用开发团队 / 移动平台团队 | 一条命令安装 CLI；`rn init` 生成工程 |
| **平台服务** | 把「包」发布、下发、回滚 | 交付 CLI（`ship`）+ 控制面服务（Docker 部署） | 运维 / 发布管理 | Docker 镜像 + 一键部署到企业自有服务器或云主机 |
| **治理与文档** | 把「谁拥有什么、禁止碰什么、怎么操作」固化 | 架构决策记录（ADR）、工程原则、角色指南、操作手册、发布清单 | 全角色 | 随平台仓库分发 |

## 3. 交付物清单

### 3.1 底层库（Runtime SDK）

| 交付物 | 能力 |
|--------|------|
| **契约与门禁库** | 设备端真 Ed25519 验签（`pem:ed25519:`，验不过即拒载，fail-closed）；运行时兼容窗判定（RN 精确版本 / Hermes 指纹 / HBC 字节码版本 / New Architecture 标志 / 原生 ABI 面）；发布单元、灰度、暂停/终止、质量门禁、软件物料清单（SBOM）门禁 |
| **引擎适配器** | 把 RN 引擎专属知识（指纹维度、版本常量、产物格式、工具链）收敛在单一适配器内；**更换引擎 = 替换适配器实现**，宿主与契约层零改动 |
| **设备端 OTA 客户端** | 设备端完整 OTA 流程（拉取清单 → 验签 → 下载 → 落盘 → 激活 → 重载）；已安装版本去重（避免每次启动重复拉包）；崩溃环检测与自动回滚到内嵌基线 |

### 3.2 框架（开发者工具链 + 脚手架）

| 交付物 | 能力 |
|--------|------|
| **开发者 CLI（`rn`）** | 一条命令安装（含预检/升级/卸载）；`init` 生成工程、`dev` 启动多模块 Metro 开发、`doctor` 全链路体检（主机 → 工程 → 发布就绪门禁）、`module` 管理业务模块工作区 |
| **工业壳脚手架** | 一键生成**产品级壳**：宿主加载器 + 模块注册表 + 设备 OTA 启动 + 失败兜底界面 + 平台包自动链接，零残留参考宿主代码 |
| **原生 OTA 模块模板** | 设备端原生槽（文件槽、激活路径持久化、已装版本记录、重载），可直接注入宿主工程 |
| **生成式注册表** | 壳对业务模块的唯一静态链接点，由工具自动重写——壳源码不出现任何具体业务模块的 import，避免"壳被业务绑架" |
| **开发会话 / Metro 解析器** | 多业务模块并行开发（多端口、热更新），模块包解析指向平台包真实路径 |

### 3.3 平台服务（发布与控制面）

| 交付物 | 能力 |
|--------|------|
| **交付 CLI（`ship`）** | 宿主/模块候选构建、签名（Ed25519）、发布预检、staging → 生产 promote、回滚 block、质量信号记录——**所有发布写操作只经交付 CLI + 控制面**，开发者 CLI 无发布权限 |
| **控制面服务（CP）** | 设备端 OTA 清单下发（按版本通道/泳道）；**内容寻址制品库**（按 sha256 存储与校验，防篡改）；版本注册库（production 窗口 + 回滚记录 + 阻塞列表）；灰度（SLO 节奏）与暂停/终止；设备泳道（灰度切片）；质量信号门禁；审计日志；鉴权 |
| **Web 控制台 / 装包台** | 浏览器查看发布状态与制品；真机安装验证台（装包 → 记录质量信号 → 审计） |
| **一键部署方案** | Docker 镜像 + Compose + 一键脚本：构建/同步 → 部署到企业自有服务器或云主机（ECS/VPS）→ 健康检查；支持镜像仓库推送或直传 |

### 3.4 治理与文档

| 交付物 | 能力 |
|--------|------|
| **架构决策记录（ADR）** | 设备信任模型、双公钥轮换、制品库接缝、引擎适配拆分、冷重建灾难恢复等关键决策的正式记录 |
| **工程原则** | 平面隔离红线（开发环 vs 交付环 vs 控制面）、发布权限、验收门禁 |
| **角色指南与操作手册** | 按「应用开发 / 移动平台 / 运维」分角色导航；含 OTA、多包版本、A/B、后端服务等操作手册 |
| **发布清单** | 从平台契约到商店提交的可执行发布门禁 |

## 4. 角色与触点

| 角色 | 主要触点 | 拥有的决策 |
|------|----------|------------|
| **应用开发团队**（业务模块） | 开发者 CLI + 模块工作区 + 多模块开发 | 业务代码、模块声明、开发端口；**不接触签名与生产发布** |
| **移动平台团队**（壳/宿主） | 工业壳脚手架 + 设备端 SDK + 原生模板 | 宿主形态、运行时兼容窗、宿主发版节奏 |
| **运维 / SRE** | 控制面部署 + 注册库/制品备份 + 灾难恢复演练 | 服务可用性、数据备份、信任根管理 |
| **发布管理** | 交付 CLI + 控制面 + 质量信号 | 生产发布 / 回滚时机（受控、可审计） |
| **质量 / 自动化** | 自动化验证链 + 设备端到端链路 | 门禁结论 |

## 5. 安全与信任

- **设备端真验签**：所有下发包携带 Ed25519 签名，设备端以内置公钥逐一验证，验签失败一律拒载（fail-closed）；发布链路拒绝非签名/弱签名产物。
- **双公钥轮换**：主签名密钥泄露时可经备份密钥签发吊销清单，设备端内置双钥，支持应急轮换。
- **内容寻址制品**：制品以 sha256 摘要为地址存储，下载后二次校验，防篡改可审计。
- **审计与鉴权**：控制面写操作带鉴权；所有发布/回滚/灰度动作写入审计日志。
- **生产签名受控**：签名密钥由发布负责人保管，发布动作经审批；自动化环境使用隔离的非生产密钥，与生产签名严格分离。

## 6. 运维与可靠性

- **灰度与回滚**：按设备泳道灰度；SLO 阈值触发自动暂停；一键阻塞问题版本，设备端回退到上一良好版本（真机验证过完整回滚闭环）。
- **质量门禁**：端到端失败信号直接拦截发布（防止带病上线）。
- **灾难恢复 = 冷重建**：每日加密异地备份 + 在任意装有 Docker 的机器上十几分钟重建恢复服务；不承诺常驻热备，架构简单、成本可控。
- **每业务独立部署栈**：每个业务 App 一套独立 Compose 栈（独立数据卷/域名/签名/反代/数据库），互不共享行级租户，隔离清晰。

## 7. 成熟度（可对外声明）

- **开发环工业可用**：工程初始化 → 多模块开发 → 发布就绪体检全链路打通。
- **候选制品可装可验**：宿主与模块候选包可构建、签名、发布到预发、真机安装验证。
- **单模块可企业推广**：签名 + promote/block 闭环，设备端验签拉包实测通过。
- **企业闭环**：灰度、回滚、质量门禁齐备；**已在真实设备上完成「发布 → 设备端验签下载 → 安装重载 → 运行」与「阻塞 → 设备端回滚到上一版本」的端到端验证**；控制面可一键部署到企业自有服务器。

## 8. 名词速查（对外术语）

| 术语 | 含义 |
|------|------|
| 宿主 / 壳 | App 的原生外壳（承载原生能力与 OTA 运行时） |
| 业务模块 | 独立交付的 RN 业务包（`modules/<id>`），非独立 App |
| 生成式注册表 | 壳加载业务模块的唯一静态入口（自动生成） |
| OTA / 离线包 | 无需发版商店即可下发的 JS 更新包 |
| 控制面 | 负责清单下发、制品存储、灰度回滚的后端服务 |
| 内容寻址 | 制品按内容摘要寻址与校验，防篡改 |
