# RN 企业级交付平台 · 一页汇报

**定位**：一个覆盖 RN App「工程初始化 → 多业务模块并行开发 → 签名发布 → 设备端 OTA 下发与回滚 → 灰度与质量门禁 → 灾难恢复」全生命周期的企业级交付平台。绿地（新应用）与棕地（嵌入既有原生宿主）走**同一条工业标准、两条路径**——不是两个产品。

## 解决什么

| 业务痛点 | 平台答案 |
|---|---|
| 版本迭代慢、发版要等商店 | 业务模块独立交付，设备端 OTA 秒级下发，无需重新发版 |
| 多团队并行互相踩 | 模块工作区隔离 + 生成式注册表，壳不依赖具体业务代码 |
| 线上事故难回滚 | 一键阻塞问题版本，设备端自动回退上一良好版本（**真机验证过**） |
| 发布不可信、不可审计 | 设备端真 Ed25519 验签（验不过拒载）+ 内容寻址制品 + 审计日志 |
| 上线质量无门禁 | 端到端失败信号直接拦截发布；灰度 SLO 阈值自动暂停 |

## 交付物一览

| 层 | 交付物 | 一句话能力 |
|---|---|---|
| 底层库 | 契约门禁库 / 引擎适配器 / 设备端 OTA SDK | 验签、兼容窗、崩溃回滚；换引擎只换适配器 |
| 框架 | 开发者 CLI + 工业壳脚手架 + 生成式注册表 | 一条命令装 CLI，几分钟生成产品级壳工程 |
| 平台服务 | 交付 CLI + 控制面服务（Docker） | 签名/发布/回滚/灰度/制品库/审计，一键部署到企业自有服务器 |
| 治理 | 架构决策记录 + 工程原则 + 操作手册 + 发布清单 | 规则固化为契约与可执行门禁 |

## 为什么可信（证据）

- **真机端到端验证**：真实设备上完成「发布 → 设备端验签 → 下载 → 安装重载 → 运行」与「阻塞 → 回滚上一版本」全闭环
- **自动化质量**：300+ 自动化测试通过；60+ 能力验证链；10 条设备端到端场景链
- **架构治理**：13 篇正式架构决策记录（ADR），工程原则红线强制
- **GF/BF 统一**：一套协议覆盖绿地新应用与既有宿主嵌入

## 安全与可靠

- 设备端 **Ed25519 真验签**（fail-closed）+ **双公钥轮换**（应急吊销）；生产签名由发布负责人保管，自动化环境用隔离密钥
- **内容寻址制品库**：sha256 存储校验，防篡改可审计
- **冷重建灾难恢复**：每日加密异地备份，任意装 Docker 的机器十几分钟重建恢复（不承诺常驻热备，成本可控）
- **每业务独立部署栈**：独立数据卷/域名/签名/数据库，隔离清晰

## 怎么接入

1. **开发**：一条命令安装 CLI → `init` 生成工程 → 业务团队在模块工作区并行开发
2. **发布**：交付 CLI 构建/签名 → 预发验证 → 生产 promote（受控、可审计）
3. **部署**：Docker 镜像一键部署到企业自有服务器或云主机（ECS/VPS），健康检查自动化
4. **运维**：灰度/回滚/质量门禁/审计开箱即用；DR 演练即「换台机器重建」

**一句话总结**：从工程到发布到设备端，全链路工业级；真机验证过、安全可审计、回滚有兜底、部署到你家。
