# RN 企业级交付平台 · 汇报 PPT 大纲（10 页）

> 面向：董事会 / 技术委员会 / 合作方评审。每页给出标题、要点、备注（讲稿提示）。
> 数据依据：[`platform-deliverables.md`](./platform-deliverables.md) · [`one-pager.md`](./one-pager.md)。

---

## 1. 封面
- 标题：**RN 企业级交付平台** —— 从工程到设备端，全链路工业级
- 副题：Greenfield + Brownfield 一条标准，两条路径
- 备注：一句话定调——"今天讲的不只是一个脚手架，是 App 全生命周期的交付体系"

## 2. 业务痛点（为什么需要它）
- 发版慢：新功能等商店审核
- 协作乱：多团队共用一个 App，互相踩
- 事故险：线上问题回滚慢、不可控
- 信任缺：发布不可审计、客户端不可验证
- 质量松：上线无门禁，带病发布
- 备注：每行配一个常见场景故事；这一页制造"痛点共鸣"

## 3. 平台定位（是什么）
- 一张分层图：底层库 → 框架 → 平台服务 → 治理
- 一句话：`rn` 造工程，`ship` 发布交付，控制面下发回滚，底层库被共用
- 备注：强调"不是工具集，是体系"；GF/BF 同一条标准是差异化卖点

## 4. 交付物一览（交付什么）
- 表格：四层 × 交付物 × 一句话能力（同 one-pager §3）
- 备注：逐层带过，突出"工业壳脚手架几分钟生成"、"一键部署到自家服务器"

## 5. 安全与信任（凭什么敢用）
- 设备端 Ed25519 真验签，验不过拒载（fail-closed）
- 双公钥轮换 + 应急吊销
- 内容寻址制品库（sha256 防篡改）+ 审计日志
- 生产签名受控（负责人保管，自动化隔离密钥）
- 备注：安全是 enterprise 采购的第一道门；这页放演示截图（manifest+签名+校验）

## 6. 运维与可靠性（上线后怎么办）
- 灰度（泳道 + SLO 阈值自动暂停）
- 一键回滚：阻塞问题版本，设备端回退上一良好版本
- 质量门禁：端到端失败信号拦发布
- 冷重建 DR：每日加密备份，任意 Docker 机器十几分钟恢复
- 每业务独立部署栈（隔离）
- 备注：这页是"运维放心"的承诺；回滚放真机录屏

## 7. 证据与成熟度（凭什么可信）
- 真机端到端：发布 → 验签 → 下载 → 安装重载 → 运行 ✓
- 真机回滚：阻塞 → 设备回退上一版本 ✓
- 300+ 自动化测试 · 60+ 验证链 · 10 条设备端到端场景
- 13 篇正式架构决策记录（ADR）
- 备注：证据页是压舱石；强调"不是 PPT 承诺，是已经跑通的"

## 8. 接入路径（怎么落地）
- 4 步：开发（一条命令装 CLI + init）→ 发布（交付 CLI 签名/发布）→ 部署（Docker 一键到 ECS/自有服务器）→ 运维（灰度/回滚/审计开箱即用）
- 时间线示例：首日跑通开发环，一周内发布首个 OTA
- 备注：给决策者"落地成本低、路径清晰"的信心；可附 PoC 计划

## 9. 与现状对比（可选页）
- 现状：自研脚本/手动发版 vs 平台：全链路受控
- 备注：若现场有对比需求再放；避免贬低竞品

## 10. 总结与行动项
- 一句话总结：真机验证过、安全可审计、回滚有兜底、部署到你家
- 行动项：① 选一个试点业务 ② 两周 PoC（真机验证发布+回滚）③ 评估推广范围
- 备注：结尾落到"下一步我们一起做"；留联系方式/仓库入口
