# 企业级 React Native 交付平台

这是本努力的领域术语表；架构与实施决策记录在地图票中。

## Language

**交付平台**:
覆盖 React Native 从创建、开发、调试、测试、构建、签名、制品、灰度到发布与运营治理的企业能力集合，由 Runtime SDK、Toolchain、Delivery、Control Plane、Governance 五部分组成。
_Avoid_: 脚手架, 公共库, 万能 npm 包

**Runtime SDK**:
App 运行时依赖的稳定契约、宿主集成层、核心服务与官方原生能力包。
_Avoid_: 把 CI、发布后台或全部业务组件算进 SDK

**运行时目标**:
平台一等支持并独立出制品行的操作系统：`ios`、`android`、`harmonyos`。
_Avoid_: 把 HarmonyOS 当成 Android 变体, 只用 Platform.OS 区分三端

**能力契约**:
与操作系统无关、可版本化的 JS/Codegen 接口与语义合同；原生实现必须满足它，而不是反向定义它。
_Avoid_: 按端各写一套业务 API, 在 JS 里堆 Platform.OS

**平台实现**:
某一运行时目标上对能力契约或宿主契约的原生兑现，包括权限清单、生命周期和构建插件。
_Avoid_: 巨型 adapters 包, 业务模块私有原生分叉

**制品行**:
同一 `release_id` 下按运行时目标独立签名、晋级和回滚的制品序列，例如 IPA、APK/AAB、HAP。
_Avoid_: 一个通用包打三端, 三端完全不关联的独立 release

**兼容配置档**:
由 `hostAppVersion`、`runtime_fingerprint`、`capability_set`、`artifact_line` 四维宿主底模生成的系统级兼容身份；对外通过 `compatibility_profile_id` 和人类可读发布列车标签暴露。
_Avoid_: 只看版本号猜兼容, 让一线角色直接理解四维拼接串

**runtime_fingerprint**:
壳内可执行运行时表面的机器指纹；至少包含 RN 精确元组、Hermes VM/compiler 身份、hbc Bytecode Version、New Architecture 状态、Codegen/TurboModule/Fabric 原生 ABI 表面。RN 版本、Hermes 包版本与 HBC Bytecode Version 不可互相替代。
_Avoid_: 只用 RN 版本号做 OTA 兼容, 以为 HBC 版本对了就能安全调原生

**JS 列车**:
生产默认开启的业务 JS/Hermes 发布路径；人对齐发布列车标签，机器按指纹匹配、能力子集与渠道政策放行。
_Avoid_: 把 JS 高频发布当成默认关闭的例外, 让业务每次手填四维

**放行档**:
同一 JS 运输管道上的放量策略分层：`needs-native`（必须换壳）、`js-standard`（可自动灰度）、`js-gated`（仍是 JS 包但默认不可自动全量）。这是企业策略层，不是 ISO 名称。
_Avoid_: 五种并列发布系统, 或所有 JS 一律自动全量

**能力探测**:
运行时查询某能力在当前运行时目标上是 `SUPPORTED`、`ADAPTER_REQUIRED` 还是 `UNSUPPORTED` 的正式结果；业务必须按结果选择路径。
_Avoid_: 静默 no-op, 假装三端行为相同

**能力清单（manifest）**:
能力包的可机读合同，声明权限/隐私影响、能力探测三态语义、错误模型、降级计划、生命周期约束、测试替身与观测字段；平台与业务据此做准入与运行时决策。
_Avoid_: 仅靠 README 文档或不可验证的约定

**通用实验契约**:
平台级 A/B 治理合同，统一变体、分桶、曝光/回收、回滚、审计、观测指标与失败预算；实验只能切换已审核的功能路径或能力参数。
_Avoid_: 业务私建实验系统或用实验绕开能力清单/权限/隐私约束

**Toolchain**:
开发者本地使用的 CLI、模板、生成器、调试、诊断和迁移工具。
_Avoid_: 零散脚本集合

**Delivery**:
把源码转化为可验证、可签名、可追溯制品的构建、测试、CI/CD 与供应链体系。
_Avoid_: 仅指应用商店上传

**Control Plane**:
管理环境、配置、版本、兼容关系、灰度、离线包、回滚、审计和紧急停发的服务端控制面。
_Avoid_: App 内的发布页面, 单个上传脚本

**执行后端**:
受企业控制面编排、可通过适配器替换的构建 runner、设备云、对象存储/CDN、观测分析或商店连接服务。
_Avoid_: 把某个供应商控制面当作企业唯一事实源

**交付事实**:
企业自己掌握的 build、release、update 身份及其策略、审批、签名、制品、符号、来源证明和审计关联。
_Avoid_: 只保留供应商任务号或临时下载链接

**同物晋级**:
同一个已验证制品从低环境原样晋级到高环境，不在 production 临门重建；若存在重签名或商店侧变换，必须保留完整链路证明。
_Avoid_: staging 过了再在 production 重建一个“等价包”

**中国区执行面**:
针对中国大陆网络、数据路径和渠道要求区域化部署或采购的依赖、构建、真机、OTA/CDN 与观测执行能力；与海外执行面共享企业控制面语义。
_Avoid_: 把一次可访问测试当作大陆生产 SLA

**发布通道**:
宿主/商店通道承载原生、权限、隐私与 SDK 变化；JS 列车承载匹配指纹的业务可执行更新（生产默认开启）；内容通道承载无脚本静态资源（v1 可并入 JS）；渠道政策可在特定 `artifact_line` 上叠加禁热更。
_Avoid_: 全国默认关闭 JS 列车, 万能 OTA 规避审核, 把 JS 当作天然合规静态资源

**发布控制面**:
统一管理发布单元、状态机、灰度、审批、回滚、失败预算与审计的服务端系统；托管宿主列车与 JS 列车，并执行放行档与渠道叠加。
_Avoid_: 业务方各自一套灰度后台, A/B 与发布系统彼此脱节

**观测契约**:
把运行时、构建与发布信号统一挂到企业自有身份上的采集与关联合同；供应商分析系统只是可替换执行后端。
_Avoid_: 把厂商 issue 号当交付事实, 业务代码直连多个专有 SDK

**错误预算**:
基于企业 SLI（crash-free、启动、更新应用、关键旅程、ANR）设定的可消耗失败额度；超限必须自动暂停对应灰度或实验。
_Avoid_: 只看告警数量或厂商 issue 数

**合规配置档**:
叠加在高敏消费级默认基线之上的监管附加合同，例如金融/医疗所需的更严审计、数据驻留、留存、审批和禁用能力清单。
_Avoid_: 把金融医疗规则做成所有 App 的默认负担

**同意链路**:
权限与隐私调用前必须经过的四段过程：声明、同意、能力探测、调用；未授权不得偷偷重试。
_Avoid_: 先调用再补弹窗, 权限拒绝后无限重试


**可执行 OTA**:
安装后从企业服务端下载并由 App 执行、可改变行为的 RN JS、Hermes bytecode、脚本、插件或 DSL；是否可执行由实际语义判断，不由文件扩展名或“离线包”名称判断。
_Avoid_: 热修复天然安全, JS 不是代码

**Governance**:
跨团队执行的安全、隐私、可观测性、质量门禁、版本生命周期、所有权和变更治理。
_Avoid_: 文档口号, 只靠人工 code review

**能力包**:
实现一个边界清晰、可独立版本化的通用设备或系统能力，并遵循平台插件契约的官方模块。
_Avoid_: 把所有设备 API 合成一个包

**业务扩展插件**:
由业务团队拥有、通过平台契约接入工具链和运行时的扩展；其生命周期不由平台内核强制捆绑。
_Avoid_: 未受治理的任意原生代码

**宿主层**:
隔离纯 RN App 与 Brownfield 原生容器差异，负责 RN Runtime、页面容器、生命周期和原生导航集成的边界。
_Avoid_: 业务壳页面, 把宿主逻辑散落在业务模块

**宿主契约**:
跨 `ios`、`android`、`harmonyos` 统一的宿主接口族，定义 Runtime 启停、Surface 管理、导航边界、前后台与异常恢复语义。
_Avoid_: 每端各写一套未对齐生命周期, 把宿主细节泄漏到业务层

**AppHostKernel**:
宿主契约中管理进程级配置、安全、观测与崩溃降级的内核接口。
_Avoid_: 在页面或能力包里分散进程治理逻辑

**RuntimeHost**:
宿主契约中管理 RN Runtime 生命周期、Bundle 装载与能力注册的接口。
_Avoid_: 让业务页面直接控制 Runtime 启停

**SurfaceHost**:
宿主契约中管理页面实例、导航容器与可见性状态的接口。
_Avoid_: 把 Surface 当作 Runtime, 跨容器共享页面状态

**兼容矩阵**:
明确原生壳、React Native、Runtime SDK、能力包、JS Bundle 与控制面协议之间允许组合关系的可机读合同。
_Avoid_: 仅靠版本号大小猜兼容

**版本通道**:
滚动管理 React Native 及其原子工具链元组的 production、next、minimum 和 exception 队列；表达生产推荐、候选验证、迁移下限与限期例外，而不是长期冻结一个版本。
_Avoid_: latest 即生产, 多个 RN minor 都是长期支持线

**薄 CLI**:
提供统一命令入口、上下文和协议编排，自身不内置所有平台实现；具体能力由可版本化插件与平台 API 提供。
_Avoid_: 万能二进制, shell 脚本目录

**宿主列车**:
按 `ios`/`android`/`harmonyos` 分轨的原生壳与 Runtime 升级节奏；默认走商店通道，维护 production/next/minimum，业务 App 必须跟车。
_Avoid_: 把 JS 发布和原生壳升级当成同一条用户放量流, 三端共用一个 runtime 窗口

**契约窗口**:
官方能力包的开发者侧版本与认证节奏；不是单独的用户放量列车。原生/权限/隐私变化必须并入宿主列车。
_Avoid_: 能力包自己开往生产用户, 却不声明宿主兼容范围

**蓝图**:
读者向组装产物，位于仓库 `blueprint/`：唯一入口、五边界专题卷、附录机读样例与验收清单；决议正文仍在 `wayfinding/issues`，蓝图只组装并追溯。
_Avoid_: 把蓝图写成第二真相源, 或把 runbook 塞进蓝图

**蓝图完成**:
本地图决策票关闭且 `blueprint/acceptance.md` 五项通过条件满足，实施团队可直接拆期；不等于平台已实现，也不要求参考骨架可运行或渠道书面回函。
_Avoid_: 用生产代码或真实上架回函定义蓝图完成

**渠道配置档**:
按分发渠道叠加在中国监管底线之上的可审计机读档案（`channel_profile`）；声明 JS 列车/自更新是否允许、商店提交字段、证据状态与过期时间。
_Avoid_: 全渠最严一刀切, 按兄弟渠道类推放行

**BLOCKED_PENDING_CHANNEL_RULES**:
因渠道现行规则证据缺失或过期而对可执行 JS 列车/自更新 APK 的机读阻断码；不撤销渠道一等身份，也不阻止已审原生商店提交。
_Avoid_: 缺口就踢出一等名单, 或允许无证据上线可执行热更

**双宿主 CLI**:
本地/诊断宿主与交付宿主切开的命令面；交付 CLI 版本钉在项目合同，不进入 app dependencies。
_Avoid_: 单一万能二进制, 把交付 CLI 塞进业务依赖

**插件三 ABI**:
CLI 命令插件、原生/能力包、预构建改写三类插件协议；发现、版本协商与校验按类隔离，禁止混 ABI。
_Avoid_: 一个插件同时冒充命令、原生模块与 prebuild
