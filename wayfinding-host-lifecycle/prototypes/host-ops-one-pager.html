多包联调（#149）— 谁需要壳仓？

业务工程师不需要 clone / 安装壳项目。 手册硬边界：业务机删除 tiangong-host 后仍须能 npm run dev + 已装 Debug Host 联调（剧本 D1）。 多包时每个业务仓各自 npm run dev；Broker 由第一个起的 rn module dev 拉起或复用。

角色需要壳仓？典型命令
业务工程师 否 — 零壳仓 cd desk && npm run dev（多包则各开终端）
host-ops 是（壳团队职责） 装 Debug Host · rn module register · 可选 rn dev 作共享基础设施

Lab 钢线（壳团队在场时推荐，非业务前置）：

① host-ops（可选）：cd tiangong-host && rn dev → ② 业务 A：cd desk && npm run dev → ③ 业务 B：cd fixture_second && npm run dev → ④ 面板 Bind · USB / Wi‑Fi 验收

① 是 host-ops 共享基础设施（壳 Metro + Broker + 全端口 reverse + 冷启回壳），不是业务开发的前置条件。 无 ① 时：②③ 仍可 Bind + 业务 HMR；但冷开 App / Return to shell 可能红屏，需 host-ops 补起壳 Metro 或重装带内嵌 shell 的 Debug Host。

分路径详情

A · 壳开发会话

模式 A · rn dev · host-profile 仓内
一条命令（日常）
cd ~/code/tiangong-host && rn dev
变体
  • 冷启 / 首装 / native 变更：rn dev --android
  • 非 cwd：rn dev --project <hostRoot>
  • 强制重装：rn dev --force-install
  • 自定义端口：rn dev --port …（保留）
Warm skip-install（#162）
  • 比对 apkSha256 + nativeDriftHash
  • 会话：.rn/host-install.session.json
  • 不单独用 versionCode（tiangong-host 长期为 1）
壳 Metro 做什么
  • 壳 JS 热更（shell/**、Dev Session 面板）
  • Broker + __host_shell__ Live + multi-port reverse
  • 未 Bind 时冷启回壳 bundle

B · 装 / 卸 / 查壳

模式 B · rn host install|uninstall|status · 默认无 Metro
一条命令（装壳）
rn host install --project ~/code/tiangong-host
对称命令
  • 卸载：rn host uninstall
  • 清数据：rn host uninstall --clear-data
  • 对账：rn host status
  • 装完顺带 Metro：rn host install --with-metro
  • iOS（planned）：rn host install --platform ios（darwin only · 见 #165）
何时用 B 而不起 Metro
  • 给业务发 APK、换机、验收嵌入 baseline
  • 设备后续只跑业务 Metro + 面板 Bind
  • 前提：接受首次打开前由 host-ops 另起 rn dev，或 APK 内嵌 shell 可冷启
与装包台并存（#94）
  • 本地 debug：rn host install
  • 企业分发：rn-delivery / CP 门户（不合并进 rn init）

C · 业务开发

rn module dev · 业务仓 · 不装壳
一条命令
cd ~/code/desk && npm run dev
前置（host-ops 一次性）
  • 设备已装 Debug Host（路径 B 或 A 的 install 阶段）
  • 壳侧 reverse 协调者在线（通常路径 A 的 rn dev）
成功判据
  • Broker 显示业务 module Live
  • Dev Session 面板 Bind 到目标 module
  • 改业务 JS → reload / HMR 生效
业务工程师不需要
  • clone tiangong-host
  • Gradle / adb install
  • 手配 adb reverse

FAQ

「起 Metro 是为了开发调试壳吗？」

不完全是。壳 Metro（路径 A）有三项职责，按优先级：

  1. 壳 JS 热更 — 改 tiangong-host/shell/**、Dev Session 面板时必须。
  2. Dev Session 基础设施 — Broker、__host_shell__ Live、multi-port adb reverse。业务 npm run dev 依赖 reverse 面；即使业务工程师不启壳 Metro，host-ops 侧通常仍要有一个协调者（路径 A 承担）。
  3. 冷启回壳 — 未 Bind / Return to shell 时，Debug 构建从壳 packager 拉 index（不是 desk 的 index）。

只装不启 Metro 用路径 B：发 APK、换机、onboarding。 必须壳 Metro 用路径 A：改壳 JS、联调面板、验证 Bind、native 变更后重装一条龙。

命令命名速查（#163 amend）

rn init脚手架 新建 RN 工程 — 永不装 tiangong-host
rn host android本机 JDK / SDK / adb 工具链（改机器）— 永不装 APK 到手机
rn host install装 Debug Host 到设备（模式 B）— 与 host android 目标不同，故可短命令
rn host uninstall从设备卸 Debug Host
rn host status设备 vs 工作区 install identity 对账
rn self uninstall卸 rn CLI 本身 — 不是卸 Debug Host
rn dev壳仓 Shell Dev Session（模式 A）
rn module dev业务仓 Metro + Live（路径 C）

拒绝 rn app install（「app」歧义）与 rn install（与 npm 习惯冲突）。 曾用 rn host app install 仅为避名；amend 后以「机器 toolchain vs 设备 lifecycle」分层，不再需要 app 中间层。
