分发服务 · 运维验证页

面向平台运维 / 发布工程师：验证分发 API 与注册表是否正常，不是给测试或业务方用的成品控制台。 企业正式环境可设 RN_CP_DISABLE_CONSOLE=1 仅暴露 API，自建装包台与发版 UI。 数据来自 .rn/delivery/registry.json；列表为空表示尚无制品入库。

名词解释
控制面 Control Plane
管「发什么、发到哪、能否回滚」的策略中心；本页是它的 Web 操作入口，真相在注册表与 API。
注册表 Registry
所有待发布/已发布制品的清单，分预发与生产两条泳道。
预发 / 生产 Staging / Production
预发 = 内测/QA 可见；生产 = 正式对用户或设备生效。晋级（Promote）把制品从预发推到生产。
制品指纹 digest
包内容的 SHA256，全平台唯一 ID。晋级、封禁、下载都认 digest，不认「内部版本号」。
宿主装包 app-host / app-host-debug
整包 APK/IPA（壳应用），给测试人员安装，不是 JS 热更新。
JS / 离线包 js-update
业务侧 JavaScript 资源包：用户已安装 App 后，在不重装整包的情况下更新页面与逻辑（类似常见 OTA 热更）。与「宿主装包」是两条线。
业务模块 business_module
多 Bundle 场景下的模块名（如 checkout、home），用于 Kill/Pause 与 JS 列表筛选。
晋级 / 封禁 Promote / Block
晋级：预发 → 生产；封禁：禁止该 digest 再被选用。
熔断 / 暂停 Kill / Pause
按业务模块紧急停更：Kill 指定 update_id；Pause 暂停整个模块下发。
灰度发布 Rollout
按阶梯逐步提高下发比例（如 5% → 25% → 100%），可中途暂停。
依赖清单 dependency-manifest
壳↔包、包↔包依赖合同；发布/晋级/运行时加载时会做门禁校验。
管理令牌 RN_CP_TOKEN
服务端环境变量；填写后，晋级/封禁等写操作需 Bearer 鉴权。

典型流程： CI 或本地打包 → 入库预发 → 本页核对 → 晋级到生产 → 装包台下 APK，或 App 内拉取 JS/离线包。 产品门户（接 API）：宿主装包台 · JS 发版台。 静态设计稿见 wayfinding-map-e/prototypes/。

JS / 离线包

接口：GET /v1/js-updates · 用量统计尚未接入 · 泳道 · 模块筛选
